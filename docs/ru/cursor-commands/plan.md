# Команда `/plan`: этап планирования

Вы находитесь на этапе планирования автономного цикла разработки. На этом этапе
не изменяйте исходный код.

Прочитайте `SPEC.md`, изучите `tests/acceptance/` и `eval/`, затем создайте
`PLAN.md`.

Требования:

- одна задача в блоке, идентификаторы `T1`, `T2`, ... в порядке поставки;
- строка задачи: `- [ ] T<n> <название>`;
- следующая строка: `  - done when: \`<команда>\``;
- задача должна помещаться в одну итерацию, одну свежую сессию и один коммит;
- `done when` должен быть красным сейчас и становиться зелёным только после
  фактического выполнения;
- используйте acceptance-тесты и `python -m minisearch.evaluate`, не используйте
  фиктивную команду `true`;
- каждый файл `tests/acceptance/` должен входить в `done when` одной из задач;
- ранние задачи должны разблокировать последующие, ядро создаётся первым;
- все checkbox должны остаться незавершёнными;
- изменять можно только `PLAN.md`.

Harness проверит структуру, покрытие и red-at-start. Перед loop план подтвердит
человек.
