# DEMO: сценарий на 30 минут

## Какой режим брать
| | brownfield | greenfield |
|---|---|---|
| Что закрывает в интервью | loop, динамический workflow, не теряться в планах | **весь пайплайн «цель → план → loop»** |
| Предсказуемость живого запуска | выше (ловушки заготовлены) | ниже (агент сам пишет всё) |
| Помещается в 8-12 мин живьём | да, T1 целиком | фаза плана + T1, остальное из записи |
| Рекомендация | запасной вариант | **основной**, если успеешь отрепетировать |

## За день до
1. Репетиция без API в unstripped-копии: `./use_mode.sh greenfield`, baseline-коммит,
   `AGENT_CMD='python3 demo/fake_agent.py' AUTO_APPROVE=1 ./loop.sh`. Потом `demo/reset.sh`.
2. Сверь с актуальной докой Cursor (я не мог запустить Cursor и `cursor-agent`):
   флаги CLI (`cursor-agent --help`: `-p`, `--force`, `--output-format`), формат `.cursor/hooks.json`
   и поля ответа hook'а, что `.cursor/rules/*.mdc` и `.cursor/commands/*.md` подхватываются.
3. Реальный прогон в **stripped**-копии (`./use_mode.sh greenfield --strip`), запиши экран как резервное видео.
   Первый реальный прогон почти наверняка потребует правок промптов: это нормально, заложи на него час.

## Ловушки
**Brownfield (подготовленные):**
- T1: в стартовом коде `hash()` рандомизируется между процессами: межпроцессный поиск даёт мусор,
  агент должен найти корень в другом модуле и добавить подзадачу.
- T2: одной правки регулярки мало (recall 0.79 при пороге 0.9): нужны ё→е, стоп-слова, стеммер.

**Greenfield (возникают сами, ничего не подсажено):**
- Агент пишет эмбеддер с нуля. Если возьмёт `hash()`, попадёт в ту же ловушку на T2; если сразу
  возьмёт `zlib.crc32`/`hashlib`, ловушки не будет, и это хорошо: скажи вслух, что harness
  проверяет результат в обоих случаях.
- Русский: тот же порог 0.9, агент сам решает, как добраться.
- Фаза плана: агент может забыть фичу или написать пустую проверку, валидатор это отклонит.

## Сетка времени (greenfield)
| Мин | Что |
|---|---|
| 0-3 | Схема: SPEC → /plan → валидатор → одобрение → loop (свежая сессия) → проверки вне агента → коммит |
| 3-6 | `SPEC.md` (контракт), `tests/acceptance/` и `eval/` как оракул, `loop.sh`, rules |
| 6-18 | Живой запуск: фаза плана (покажи отказ валидатора, если случится), одобрение, T1, начало T2 |
| 18-25 | Из записи/репо: `git log --oneline`, `git log -p -- PLAN.md`, `.loop/metrics.csv`, `PROGRESS.md`, `last_failure.txt` |
| 25-30 | Trade-off'ы и вопросы |

Для brownfield: пропусти фазу плана, на 6-18 мин запусти T1 (+T2), остальное так же.

## Что показать в разборе
- `iter N: ... FAIL [replanned]` в `git log`: перепланирование видно в истории.
- `🚫 protected path touched` и `🚫 illegal plan edit`: агент полез в оракул или переписал план, harness откатил.
- Агент не ставит галочки и не коммитит: это делает loop после своей проверки.
- Фаза плана: `plan rejected by the harness` → вторая попытка.

## Вопросы, которые зададут
- **Чем лучше Agent mode в IDE?** Воспроизводимость, свежий контекст, проверки вне агента, лимиты, работа без человека.
- **Почему свежий контекст?** Длинная сессия деградирует и тащит ошибки; состояние в файлах можно ревьюить и откатывать.
- **Как агент не обманет проверки?** Оракул и план защищены: откат делает harness, галочки тоже; план может только расти подзадачами.
- **Зачем валидатор плана?** План агента не доверенный: проверяем форму, покрытие оракула и что каждая проверка красная сейчас.
- **Что если зациклится?** `MAX_FAILS` подряд без перепланирования → `[!]` и эскалация; `MAX_ITER`; `ITER_TIMEOUT`.
- **Стоимость?** Пока в метриках только время; следующий шаг: токены и деньги за итерацию.
- **Что улучшить?** Параллельные worktrees, ревью-агент перед merge, метрики стоимости, hidden-eval, который агент вообще не видит.

## Скажи сам, раньше, чем спросят
- Eval маленький (14 запросов на язык): демонстрация метода, не бенчмарк.
- Стеммер примитивный, эмбеддер не семантический: «semantic» здесь условное название.
- Оракул написан человеком и виден агенту в репо; усиление: hidden-eval вне репозитория.
- `.cursorignore` и `--strip` снижают риск подсмотреть эталон, но не гарантируют.
