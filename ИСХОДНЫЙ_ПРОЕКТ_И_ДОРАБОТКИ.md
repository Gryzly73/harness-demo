# harness-demo: исходный проект и выполненные доработки

## 1. Исходный проект

Точная первоначальная версия сохранена в коммите:

```text
aedb571 Original harness-demo baseline
```

Проект представлял собой демонстрацию Agentic Harness на примере `minisearch`.
В нём были предусмотрены два сценария:

- brownfield — работающий поисковик с тремя незавершёнными функциями;
- greenfield — пустой `src/`, спецификация и защищённые acceptance-тесты.

Уже присутствовали `SPEC.md`, режимы, Bash-loop, Cursor rules и hooks,
демонстрационный fake-agent, тестовые данные и reference solution.

### Ограничения исходной версии

- запуск был рассчитан на Bash и POSIX-утилиты;
- PowerShell-сценария не было;
- использовались `timeout`, `seq`, `sha1sum`, `tail` и associative arrays;
- hooks вызывали `python3`, которого обычно нет в Windows PATH;
- `done when` исполнялся через `bash -c`;
- актуальная команда Cursor Agent CLI на Windows не была проверена;
- реальный полный прогон не выполнялся;
- документация не подтверждала результат воспроизводимым Git-артефактом.

## 2. Инфраструктурные доработки

Кроссплатформенная версия сохранена в `main`, коммит:

```text
13dc4b5 Add cross-platform greenfield harness
```

Добавлены:

- Python-orchestrator `harness/loop.py`;
- PowerShell wrappers `loop.ps1`, `use_mode.ps1`, `reset.ps1`;
- тонкие POSIX wrappers для прежнего сценария;
- кроссплатформенный выбор режима;
- поддержка Windows launcher `agent.cmd`;
- timeout и завершение дерева процессов;
- метрики, лимиты ошибок и итераций;
- автоматические Git-ветки и коммиты;
- откат защищённых файлов;
- тесты безопасного разбора команд.

Hooks переведены с `python3` на активный Python, а post-edit lint запускается
через `sys.executable -m ruff`.

## 3. Безопасность проверок

Проверки из `PLAN.md` больше не передаются в shell. Валидатор разбирает команды
и допускает только объявленные варианты `pytest` и
`python -m minisearch.evaluate`, включая безопасную последовательность через
`&&`.

Это предотвращает выполнение произвольной команды, которую агент мог бы
записать в критерий готовности.

Защищены:

- `SPEC.md`;
- `tests/acceptance/`;
- `data/` и `eval/`;
- `src/minisearch/evaluate.py`;
- `harness/`;
- управляющие scripts и `.cursor/`.

## 4. Greenfield plan phase

Перед loop агент получает только цель и проверочный оракул и создаёт `PLAN.md`.
`harness/validate_plan.py` проверяет структуру, покрытие acceptance-тестов,
допустимость команд и красное состояние критериев до реализации.

После этого действует human approval gate. В автоматической репетиции его можно
явно пропустить через `AUTO_APPROVE=1`.

Изменение исходных задач после утверждения запрещено. Агенту разрешено только
добавлять обоснованные дочерние задачи, поэтому динамический план не теряет
связь с исходным контрактом.

## 5. Реальный контрольный прогон

Чтобы исключить доступ к готовому решению, создана физически очищенная ветка:

[`greenfield-real-baseline`](https://github.com/Gryzly73/harness-demo/tree/greenfield-real-baseline)

Её коммит:

```text
24924b7 Prepare stripped greenfield baseline
```

Из ветки удалены `modes/`, `demo/` и `DEMO.md`, а `src/minisearch/` оставлен
пустым. Cursor Agent самостоятельно сформировал следующий план:

1. T1 — ядро, CLI и английский recall.
2. T2 — сохранение индекса и межпроцессный CLI.
3. T3 — русский поиск без регрессии английского.
4. T4 — фильтрация по языку.

План прошёл внешний валидатор и был зафиксирован отдельным коммитом.

## 6. Реализация поисковика агентом

### T1 — ядро

Созданы модель документа, загрузчик JSONL, токенизатор, hashing embedder,
in-memory индекс, cosine ranking и CLI-поиск. Английский `recall@3` достиг
`1.000`.

### T2 — persistence

Добавлены `Index.save`, `Index.load`, CLI-команда `index` и поиск через
`--index`. Индекс корректно используется другим Python-процессом.

### T3 — русский язык

Добавлены кириллица, нормализация `ё → е` и Snowball-подобный русский стемминг.
Русский `recall@3` достиг `1.000`, английский остался `1.000`.

Первая попытка T3 получила внешнюю ошибку:

```text
permission_denied: Cursor is not available in your region
```

Harness зафиксировал `FAIL`, сохранил состояние и запустил свежую сессию.
Повторная итерация успешно выполнила задачу.

### T4 — языковой фильтр

Добавлены `Index.search(..., lang=None)` и CLI-параметр `--lang`.

## 7. Подтверждённый результат

Функциональная версия опубликована в ветке
[`loop/1008-130105`](https://github.com/Gryzly73/harness-demo/tree/loop/1008-130105).

История:

```text
plan: validated and approved
iter 1: T1 DONE
iter 2: T2 DONE
iter 3: T3 FAIL
iter 4: T3 DONE
iter 5: T4 DONE
```

Независимая финальная проверка:

```text
15 passed
Ruff: all checks passed
recall@3 [en] = 1.000
recall@3 [ru] = 1.000
```

Нарушений защищённых путей — `0`. Суммарное агентское время — 1034 секунды.

## 8. Было и стало

### Было

- концептуальная двухрежимная демонстрация;
- Bash-only запуск;
- потенциально опасное выполнение проверок через shell;
- непроверенные Windows hooks и Cursor CLI;
- отсутствие настоящего greenfield-прогона.

### Стало

- нативный запуск на Windows и сохранённый POSIX-сценарий;
- единая Python-логика orchestrator;
- безопасный валидатор команд;
- greenfield plan phase с coverage/red-at-start validation;
- human approval gate;
- актуальный и проверенный Cursor Agent CLI;
- настоящий stripped greenfield-прогон;
- восстановление loop после внешнего сбоя;
- опубликованные baseline и result branches;
- проверенный поисковик, созданный агентом с нуля;
- пользовательская, Harness- и сравнительная документация.
